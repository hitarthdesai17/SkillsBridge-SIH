# Phase 02: Bugs Encountered

| Bug ID | Date | Area | Symptom | Expected Behavior | Actual Behavior | Root Cause | Fix | Verification | Prevention | Lesson Learned |
|---|---|---|---|---|---|---|---|---|---|---|
| BUG-02-01 | 2026-08-19 | Database Setup | Supabase Cloud database tables were missing prior to DDL migration execution. | App queries real Supabase PostgreSQL instance | `/api/test-db` returned error: `Could not find table public.opportunities` | DDL migration script had not been run in Supabase SQL Editor. | Created `supabase/migrations/20260819_init_schema.sql` and `/api/test-db` auto-seeder utility. | Host reachability confirmed via `/api/test-db`. | Run integration queries (`SELECT count(*)`) against cloud database. | Always verify table existence in database schema cache before inserting seed records. |
| BUG-02-02 | 2026-08-19 | Database Seeding / RLS | `/api/test-db` returned `actual_records_count: 0` despite auto-seeding being executed. | Seed script upserts 16 opportunity records into Supabase `opportunities` table. | `/api/test-db` returned `seed_errors`: `new row violates row-level security policy for table "opportunities"`. | The RLS policy on `opportunities` only granted `SELECT` access, blocking `INSERT`/`UPSERT` operations for public client connections. | Updated `supabase/migrations/20260819_init_schema.sql` to grant `ALL` (SELECT & INSERT) policy `opportunities_all_policy` on `opportunities` and `opportunity_requirements`. | Tested `/api/test-db` diagnostic endpoint. | Configure RLS policies to allow seed/reference table writes for seed clients. | Never swallow insert error messages; surface detailed RLS policy errors in diagnostic logs. |

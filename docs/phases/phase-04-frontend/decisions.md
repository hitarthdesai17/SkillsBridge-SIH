# Phase 04: Architectural Decisions Log

| Decision ID | Date | Component | Decision | Rationale | Alternatives Considered | Status | Impact |
|---|---|---|---|---|---|---|---|
| DEC-04-01 | 2026-08-19 | Architecture | Enforce zero business logic duplication in React components. All readiness score calculations and reassessment simulations must execute in backend engine route handlers. | Guarantees single source of truth for readiness formulas ($0.50 S_{\text{match}} + 0.30 E_{\text{proof}} + 0.20 X_{\text{align}}$) and prevents drift between frontend UI and backend services. | Recalculating readiness scores inside React `useState` hooks | LOCKED | Clean separation of concerns; backend engine handles math. |
| DEC-04-02 | 2026-08-19 | Opportunity Marketplace | Keep unready (`NOT_READY`) opportunities visible in the dashboard feed with clear visual badges rather than filtering them out. | SkillBridge is an AI career readiness & pathway engine, not an ATS job gatekeeper. Candidates must see reachable pathways for unready roles. | Hiding roles where score < 60% | LOCKED | Transparent career discovery marketplace. |
| DEC-04-03 | 2026-08-19 | Reassessment Engine | Implement dedicated `/api/readiness/simulate` API route handler to execute simulated project completions in memory against the deterministic backend engines. | Ensures reassessment simulator returns exact score deltas and state transitions calculated by the production readiness engine. | Hardcoding static +15% UI text | LOCKED | Real-time, engine-verified score simulation. |
| DEC-04-04 | 2026-08-19 | Auth Architecture | Use `@supabase/ssr` with Next.js 14 App Router Middleware for session handling and route shielding. | `@supabase/ssr` is the official standard for managing cookie-based auth in Next.js Server Components, Actions, and Route Handlers, ensuring seamless SSR and token refresh. | Custom JWT cookies or legacy `@supabase/auth-helpers-nextjs` | LOCKED | Production-grade cookie persistence and route protection. |
| DEC-04-05 | 2026-08-19 | Password Policy | Implement dual-layer (client UI + server Zod) 5-point password policy (8+ chars, uppercase, lowercase, number, special character). | Prevents weak account credentials while providing real-time visual checklist feedback on the signup form. | Client-only regex or basic HTML5 `minlength` | LOCKED | High security with accessible UI feedback. |
| DEC-04-06 | 2026-08-19 | User Data Isolation | Bind all candidate profiles, skills, projects, experiences, and resume uploads directly to the authenticated Supabase `user_id` backed by multi-tenant RLS policies. | Ensures strict tenant isolation where User A cannot view or tamper with User B's career and resume data. | Client-passed user IDs or localStorage state | LOCKED | Multi-tenant security enforced at the database layer. |
